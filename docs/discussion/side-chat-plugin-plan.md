# 侧聊插件开发方案

## 摘要

本提案让用户在主任务继续执行时，从右侧面板发起独立问答。首版通过新插件组合已有会话、上下文引用、聊天 Factory 和右侧标签机制，默认不修改普通聊天、fork、子代理或 Agent 执行循环。

状态：P0 已进行本地验证，方案待审核，功能尚未实现。验证日期：2026-10-20。独立运行、上下文持久化和冷恢复已有测试依据；完整面板生命周期和可选部署装配尚未闭环，因此不宣称全部 P0 验收通过。首版按个人自用、单用户环境开发，非 owner 和共享会话支持不属于本次范围。本次文档提交仅包含中文提案及单页翻译排除登记，不包含生产功能或测试代码。

本文选择“独立新会话加已有上下文引用”，不选择完整事件 fork。上下文范围因此是已有引用服务提供的文本快照，不能宣称与主模型当前请求完全相同。该范围是本提案需要确认的产品约定。

<a id="scope"></a>
## 目标与范围

首版提供每个主聊天一个关联侧聊。用户可以连续追问，并在关闭面板或重新连接后恢复侧聊历史。

| 场景 | 首版要求 |
|---|---|
| 打开入口 | 主聊天头部的动作 Slot 增加“侧聊”；打开空面板不创建 Session |
| 首次提问 | 创建独立普通 Session，准备主聊天文本快照，并发送问题 |
| 主任务运行中 | 主任务继续执行；侧聊发送、失败、停止均只作用于侧聊 |
| 连续追问 | 使用侧聊自己的历史，不重新读取主聊天 |
| 关闭面板 | 释放视图资源，不取消回答、不删除历史 |
| 切换或刷新 | 按主聊天找回关联侧聊，恢复已有消息和运行状态 |
| 模型与工具 | 使用配置指定的问答 preset 和有效模型；首版不装配执行、写入或委派工具 |
| 左侧聊天列表 | 允许侧聊作为普通会话出现，以免引入列表过滤或导航流程改造 |
| 窄屏 | 复用已有右侧面板的窄屏全屏行为 |

首版不包含选中文本提问、多个侧聊、自动同步主聊天、采用回答回主聊天、读取文件、图片内容继承、工具原始结果继承和侧聊内再次创建侧聊。主聊天来源可以是当前可读会话，但侧聊始终使用独立普通 Session，不获得来源 Agent 的运行时所有权。

## 现有扩展点核对

以下结论来自对应代码和说明的静态核对。链接指向已有实现，不表示新插件已经通过集成测试。

| 能力 | 已有依据 | 本方案的使用方式 |
|---|---|---|
| 头部动作扩展 | [Conversation Slot 声明](../../packages/client/ui-conversation/src/client/contract/slots.ts) | 注册 `conversation.session.header.actions`，不编辑主聊天头部 |
| 内嵌聊天 | [Factory 注册](../../packages/client/ui-conversation/src/client/apply.ts)与[现有侧栏聊天](../../packages/client/ui-subagent/src/client/sidebar-chat/index.tsx) | 在新插件内绑定独立 `SessionProvider`，调用 `conversation.content` 的 `embedded` 变体 |
| 标签与资源生命周期 | [右侧面板](../../packages/client/ui-sidebar-right/README.zh.md) | 注册新标签类型和资源 Provider，复用布局、缩放、持久化与窄屏展示 |
| 独立 Agent | [Agent 公共接口](../../packages/core/agent/README.zh.md) | 通过 `ctx.agents.create()` 创建普通根 Agent，不传 `parentAgent`，不创建 subagent |
| preset 装配 | [preset registry](../../packages/preset/agent-preset-registry/README.zh.md) | 在 unpublished setup 中调用公共装配接口，让冷恢复沿用已记录的 preset |
| 上下文引用 | [session-reference](../../packages/context/session-reference/README.zh.md)及其[prepare 实现](../../packages/context/session-reference/src/index.ts) | 调用 `sessionReferenceResolver.prepare()`，复用快照、预算、来源标识和遗漏说明 |
| 模型输入持久化 | [Session 日志](../../packages/core/session/README.zh.md) | 复用 `user/message` 和 `session-reference` source，让实际使用的上下文进入侧聊日志 |
| 业务关联存储 | [storage-domain](../../packages/storage/storage-domain/README.zh.md) | 保存主会话到侧聊的关联及创建状态，不扩展 SessionHeader |
| 独立 Remote 服务 | [Remote 与 API 规则](../defensive-patterns/remote-and-api.zh.md) | 新能力的 Remote 方法属于侧聊插件，不向通用 Session Controller 增加侧聊分支 |

`conversation.content` 已经是公共 Factory，因此不需要先抽取 `ui-subagent` 的内部组件，也不需要新增公共聊天 Factory。实现只参考其组装方式，不能运行时导入其他 UI 功能插件的内部组件或服务实现。

现有 `session/fork` 默认继承来源 preset，并在省略事件位置时选择最近完成轮次。首版不调用它，因而不需要处理历史 preset 覆盖、继承工具声明、未完成工具调用收尾或 fork 导航行为变化。

<a id="composition"></a>
## 插件组成与修改范围

新增两个功能包和一个可选装配包。以下名称是拟定名称，尚不存在；最终登记必须遵循仓库包命名、依赖分类和生成规则。

| 拟新增目录 | 职责 |
|---|---|
| `packages/session/side-chat/` | Host 服务、Remote 方法、关联存储、创建协调、上下文初始化及 scoped 插件入口 |
| `packages/client/ui-side-chat/` | 头部入口、标签类型、资源 Provider、空面板、会话绑定、状态和本地化文案 |
| `packages/bundle/side-chat/` | 可选 Cordis patch，装配 Host、Client 和问答 preset，并声明已有依赖 |

Host 包拥有服务定义、默认实现和生成的 Remote 类型；Client 通过注入服务及生成的 Remote 客户端消费它。职责可以放在同一 Host 包的不同模块中，不为了形式额外拆包。所有注册和释放使用 `ctx.effect()`、`ctx.on()` 或已有注册接口返回的 disposer。

问答 preset 由装配包声明。它包含侧聊初始化插件、现有 persona 及必要的会话能力，不能直接复用仍包含执行工具的现有 minimal preset。空 preset 也会继承全局工具，因此 scoped 插件必须显式调用 `tools.restrict({ allow: [] })`。该限制不会屏蔽本作用域注册的工具或保留的 PTC 传输；装配必须选择原生工具呈现，并在装配完成和模型请求前验证 `tools.schemas(agent)` 为空，非空则拒绝执行。不能只检查 preset 声明，也不能省略 `agent` 参数而误检全局工具集合。

| 修改类别 | 允许范围 |
|---|---|
| 主要新增 | 三个新包的源码、README、语言字典、测试及装配文件 |
| 仓库接入 | 必要的依赖清单、锁文件、TypeScript 引用、包分类和生成的 Remote/文档登记 |
| 行为说明 | 新包文档与必要的现有索引链接 |
| 默认不修改 | `agent-loop`、既有 `session/fork`、`api/session-controller` 的业务逻辑、`ui-subagent`、`ui-chat`、`ui-conversation`、`ui-sidebar-right` 的业务实现 |
| 默认不修改 | Desktop 启动、Web 启动、全局输入状态机、既有 Session 发送/停止/权限判断 |

首版使用独立可选 patch 验证与启用，不把功能默认塞入 `web-app/cordis.patch.yml`。正常关闭插件后，普通聊天应维持原有能力；已经产生的侧聊保留为可读历史。继续运行依赖已移除 preset 的侧聊应明确报错，不能静默改用标准执行 preset。

如果扩展点验证发现必须修改默认不修改的代码，先补充最小扩展点提案，说明调用者、影响范围和回归证据，再由用户确认。不得为继续推进而复制整个聊天实现、绕过访问控制或导入包内私有 Controller。

<a id="flow"></a>
## 会话与上下文流程

上下文准备发生在侧聊首次问题进入首个模型步骤时，而不是点击“侧聊”按钮时。界面应以实际记录的来源位置说明快照，不能声称精确截取了点击发送瞬间的全部流式内容。

```text
主聊天 A 继续运行
        |
        +-- 头部入口打开右侧空面板
                  |
                  +-- 首次发送：插件确保关联会话 B 存在
                            |
                            +-- 绑定 B，通过既有输入机制提交问题
                                      |
                                      +-- B 的 scoped pre-step 扩展准备 A 的引用快照
                                                |
                                                +-- 问题和引用进入 B 的既有日志
                                                          |
                                                          +-- B 独立回答并接收追问
```

侧聊服务只负责确保目标会话和关联存在，后续发送、停止、流式消息与历史读取走已有 Session 能力。首条消息也应复用既有提交身份和回显机制；不另写一套 prompt RPC 或流式协议。

问答 preset 内的 scoped 初始化插件仅处理本侧聊第一次直接用户输入，在既有 `agent/pre-step` 扩展点调用 `next()` 并保留其决定，再通过引用服务准备背景消息。它必须保持用户身份、问题顺序、消息标识和引用 source，不能把父会话文本提升为系统指令。P0 组合使用 `prepend: true`，在 `next()` 返回后检查既有引用监听器已经准备的消息；若来源已在本批消息中，不再重复准备。

成功进入日志的首个引用快照是后续上下文依据。模型重试不得重新抓取来源；尚未提交快照就失败时，界面明确显示初始化未完成，用户显式重试可以重新准备，并显示新的实际截取位置。该区别避免把尚未持久化的准备结果宣称为固定快照。

插件应注册可重建的 Session projection，从已有 `user/message` 引用记录判断来源快照是否已提交，并提取其来源位置。重启后依赖该投影判断初始化状态，不依赖进程内布尔值，也不通过自行扫描持久文件恢复消息。P0 已验证最小布尔投影；正式投影仍需覆盖来源身份、截取位置和裁剪信息。

preset 插件在共享的组合代际中激活，Agent 加入相应作用域，不保证每个 Agent 都重新执行一次插件 `apply`。初始化监听器必须根据事件携带的 `agent` 查询关联和投影；不能在共享闭包中保存单一来源身份或“已经初始化”标记，否则不同侧聊会互相污染。

### 上下文包含什么

首版沿用引用服务现有投影和预算，不新增上下文提取器，也不调用模型额外生成摘要。

| 内容 | 首版处理 |
|---|---|
| 主聊天用户文本、助手文本 | 包含在有预算限制的引用快照中 |
| 当前有效压缩摘要 | 使用现有引用投影支持的 checkpoint |
| 工具原始结果、思考块、其他注入上下文 | 不包含；助手已经用文字解释的部分可随助手文本进入 |
| 图片、文件二进制和工作区当前文件 | 不读取，不自动继承 |
| 尚未提交的流式片段 | 不承诺包含，以 `capturedThroughSeq` 为准 |
| 超预算历史 | 复用现有保留策略及遗漏记录，界面明确显示上下文已裁剪 |
| 截断后的完整 spill | 仅视为已有引用服务的可选产物；无工具问答不承诺读取其完整内容 |

这项取舍使首版能不改 fork 和模型消息重建流程。如果产品要求侧聊看到完整工具结果或与主请求一致的原生消息序列，应另行评估扩展引用服务或使用完整 fork，不能在当前实施中悄悄扩大范围。

<a id="recovery"></a>
## 数据、恢复与权限

持久化遵循已有数据所有权。新插件保存关联和协调状态，消息及真正进入模型的上下文仍由 Session 日志保存。

| 数据 | 所有者 |
|---|---|
| 主会话身份、侧聊身份、创建请求身份、创建阶段、记录版本 | 侧聊插件独立 storage-domain |
| 首次快照内容、截取位置、裁剪信息、用户问题与回答 | 侧聊 Session 的既有消息/source 记录 |
| 模型和 preset | 已有 Agent 与 preset 持久化机制 |
| 标签身份、宽度、展开状态 | 现有右侧布局存储 |
| 输入草稿、滚动位置 | 现有会话输入服务及聊天视图机制；不承诺新增跨重启草稿保存 |

首版不向主聊天追加关联事件，不改变其模型输入。侧聊关联也不写进 `SessionHeader`，不新增 `SessionEventMap` 判别值。storage-domain 和 projection 的新 schema 仍需按仓库持久类型规则检查和登记，不能把“不改 Session 格式”理解为“不需要持久化审查”。

拟定 Remote 能力只有查询关联和确保侧聊存在，例如 `sideChat.lookup` 与 `sideChat.ensure`；名称和类型必须由服务定义生成。`ensure` 接收来源会话和稳定请求身份，返回同一个目标 Session，不接收伪造的调用者身份，也不替代普通 Session 的发送接口。

创建采用按来源会话串行的单 Host 协调：先持久分配目标身份，再创建同身份 Session，最后提交可用关联。关联阶段写入和 Session 创建之间没有跨存储事务，因此恢复必须分别识别“已分配但未创建”“已创建但关联未完成”“已就绪”。重复请求或多窗口同时请求只能得到同一个目标；多 Host 共同写同一存储不属于首版支持范围。

若 Session 已创建而首次消息失败，保留会话和可恢复状态；若发送结果未知，沿用既有请求身份查验接受结果，不自动再次提交。来源或目标已删除、归档、无权限或需要迁移时，应遵循已有读写规则并显示原因，不能无声创建替代会话或恢复执行。

每个 Remote 方法必须声明涉及的来源、目标及工作区资源，并从 invocation 获取身份。每次准备来源快照都要重新确认读取权限；内置 `prepare()` 是进程内能力，调用它不能被当作已经完成用户授权。普通目标 prompt 权限也不能替代来源读取权限。P0 已确认 `remoteAccess.allows()` 在 Remote 调用之外返回允许，因此不能在后台 pre-step 中用它校验用户权限；`remoteAccess.decide()` 的现有文档限定为 Gateway 内部使用，也不能直接作为功能插件的公共授权接口。

首版面向个人自用、单用户环境，沿用现有可信 owner 身份与权限机制，不开发共享会话或多用户授权能力。新增入口识别服务端身份，不接受客户端自报，也不因个人自用而绕过现有检查。非 owner 支持不阻塞本次插件开发；将来需要开放其他身份时，再评估后台来源授权与权限撤销。

关闭标签只释放 Client 资源引用，不能处置 Host AgentHandle 或调用 cancel。Host 插件负责它创建的 handle 和关联协调任务的生命周期；侧聊运行与主 Agent 生命周期解耦。插件卸载须停止并释放自身仍持有的运行资源，保留已持久化历史，不触碰主任务。冷恢复后 handle 的实际所有者、preset 初始化和停用行为必须通过扩展点验证，不能让两个所有者重复清理。

P0 已验证普通 Session Controller 能冷恢复侧聊并重新装配已记录 preset。创建时必须在 setup 中安装模型选择和 preset；`agents.create()` 本身不等于完整应用装配。缺失 preset 的续聊探针会报错且不发模型请求，但用户可读错误和运行中卸载仍需单独验证，不能将冷恢复成功扩大解释为整个生命周期已完成。

<a id="ui"></a>
## 界面与配置

界面使用已有注册体系。空面板的草稿属于插件声明的视图 store；目标 Session 确定后，仅将用户主动提交的草稿交给该 Session 的既有输入动作，再切换到内嵌聊天。

头部动作注册到现有 `conversation.session.header.actions`。新标签注册到 `sidebarRightTabs`，其 body 注册到 `sidebar.right.pane.tab`；标签地址只包含恢复所需身份，不包含提示词、快照正文或权限信息。资源 Provider 持有目标 `SessionReference`，通过 `SessionProvider` 建立目标会话作用域，再渲染 `conversation.content` 的 `embedded` 变体及固定 Chat view。

优先复用既有引用上下文的展示，不增加自定义消息渲染器。面板只补充“侧聊”“基于主聊天文本快照”“上下文已裁剪”等必要说明。首版不为了隐藏模型选择、附件按钮或其他共享控件而改公共输入框；不支持的操作必须由问答配置明确拒绝，扩展点验证需检查现有控件是否会造成误导，并在实施前确定局部 Slot 覆盖。

配置至少明确问答 preset 身份和部署选定的模型策略。上下文预算继续由已有引用服务配置所有，首版不修改全局引用预算默认值；如果必须提供仅侧聊生效的预算，先验证独立 scoped 实例装配，不添加共享服务中的侧聊条件分支。

所有新增文案进入语言字典；图标、按钮、提示和样式使用现有组件与 token。验收覆盖明暗主题、390px 窄屏、键盘操作和桌面标题栏空间；不新增 Electron 原生窗口。

<a id="delivery"></a>
## 实施步骤与验收

完整开发前必须确认下节列出的 P0 待定范围，并补足与所选范围相关的验证。当前可以确认插件组合具有实现基础，尚不能确认完整产品已满足验收。

| 步骤 | 交付与退出条件 |
|---|---|
| P0 扩展点验证 | 用测试组合验证独立 Agent 创建/冷恢复、现有 Factory、首次上下文准备、权限和面板关闭生命周期；不得修改默认不修改的代码来让验证通过 |
| P1 Host 插件 | 完成关联存储、幂等协调、问答 preset、scoped 初始化和独立 Remote 能力 |

<a id="p0-results"></a>
## P0 验证结果与审核项

本轮使用真实 Cordis Loader、Agent loop、Session、JSONL 持久化、引用服务和 preset registry 组合；模型通过内存适配器模拟，部分外围服务由仓库既有测试辅助设施提供。本地 P0 探针 `scripts/side-chat-p0.spec.ts` 不随本次文档提交收录，也不注册正式侧聊功能。它不能代替支持的 `dsh` profile、真实模型或浏览器验收。

| 验证内容 | 结果与证据范围 |
|---|---|
| 主任务运行中独立回答 | 通过；主请求保持运行，侧聊不是主 Agent 的子任务，来源日志没有侧聊写入 |
| 独立停止 | 通过；停止侧聊后主请求仍运行，其取消信号未触发 |
| 固定来源快照与追问 | 通过；主聊天新增内容后侧聊仍使用首次快照，引用只准备一次 |
| JSONL 冷恢复 | 通过；销毁旧 Context 后经普通 Session Controller 续聊，preset 重新装配，已有引用不重新准备 |
| 用户首问已引用主聊天 | 通过；与现有引用监听器组合后只生成一份来源快照 |
| 首次引用准备失败 | 通过；没有模型请求和已提交引用；显式再次提问后可正常初始化 |
| preset 缺失 | 通过拒绝执行检查；续聊报错且没有模型请求，未回退到执行 preset |
| 无工具问答 | 负例确认空 preset 会继承全局工具；scoped 限制可屏蔽继承工具，但作用域内新增工具仍然可见，正式实现必须校验最终集合 |
| 后台来源授权 | 负例确认脱离 invocation 的 `allows()` 不执行非 owner 检查；当前实现路径不足以承诺共享会话支持 |
| 现有引用、fork、preset、权限、Factory 和资源引用 | 9 个既有测试文件、183 个用例通过；这些是原机制回归证据，不是新侧聊面板端到端证据 |

新增探针共 9 个用例通过。保留本地探针文件的工作区可用 `pnpm exec vitest run scripts/side-chat-p0.spec.ts` 复现；仅检出本次文档提交不包含该文件。既有回归范围为 `packages/context/session-reference/tests/{session-reference,loader-composition}.spec.ts`、`packages/api/session-controller/tests/{reference-ownership.client,remote-access.host,session-presets.host,session-fork.host}.spec.ts`、`packages/client/ui-subagent/tests/sidebar-chat.client.spec.tsx`、`packages/client/ui-conversation/tests/{apply-wiring,skeleton}.client.spec.tsx`，使用 `pnpm exec vitest run` 执行这些文件。

以下项目仍需作为后续实施的前置验收，不能从上述测试推断已经通过：

1. 核对个人自用实例沿用可信 owner 身份；非 owner 和共享会话不纳入本次验收。
